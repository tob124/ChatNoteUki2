# ChatNoteUki 下一轮功能候选

调研日期：2026-10-09。本报告在 0.4.0 的安装、升级、离线与重启验收完成后整理。候选是提案，尚未自动实施，下一轮由用户选择范围。优先解决“找回想法、核对依据、形成观察”，再扩大输入方式。

## 调研范围与证据

查阅 13 个外部工具的官方文档、公开产品页面或官方源码，并检查用户自己的 Flownote 完整本地工程与公开仓库。实际观察了 Reflect 公开 AI 演示的选中文字、结果浮层和插入入口；其他工具依据官方流程、文档配图和公开示例，未声称全部安装或登录实测。Windows 可用性、付费方案和性能需在候选选定后单独验证；下表不把厂商宣传当成本机验收结果。

以下每卡的“流程”是针对 ChatNoteUki 的设计推导，不表示参考产品已经实现了所有步骤。稳定性成本表示新增数据、任务与恢复路径的复杂度，不是价格或工期承诺。

## F01 · 保存常用查询

**问题：** 经常重复输入同一组词、切换范围和筛选，回到结果时容易丢位置。

**来源：** [Reader 保存筛选视图](https://docs.readwise.io/reader/docs/faqs/filtered-views)。

**流程：** 输入关键词 → 选择问题、收藏或更正历史范围 → 保存视图并命名 → 左侧次级入口重开 → 恢复筛选和阅读位置。无结果保留条件，可一键清除；保存的是查询条件，不复制笔记。

**适配：高；优先 P1。** 0.4 已有搜索与导航恢复，增量是可命名的持久查询。默认最多展示用户置顶的几个，避免左栏膨胀。

**稳定性成本：低。** 查询字段版本化，线程归档或删除后显示失效范围；云端恢复条件，本机保留阅读位置。**最小验证：** 5 个视图、1 万条笔记，更正、删除、恢复后结果随真实数据变化，打开首屏仍只有一页。

## F02 · 有方向的笔记关联

**问题：** 同一想法跨问题出现；只靠线程树会把联系藏起来。

**来源：** [Obsidian 反向链接](https://obsidian.md/help/plugins/backlinks)。

**流程：** 在卡片菜单选“关联笔记” → 搜索并选择 → 标记补充、不同判断或后续变化 → 原卡片显示关系，目标右侧显示反向关联 → 随时取消关联。AI 可以提出关系，用户确认后生效。

**适配：高；优先 P2。** 保留现有两层线程，关联不改变归属，不复制正文。

**稳定性成本：中。** 关联使用稳定 ID 和引用版本，删除显示占位，恢复可重新核对，禁止 AI 批量自动连线。**最小验证：** 20 条跨问题笔记；更正、回收站、永久删除与恢复均不产生失效跳转或幽灵正文。

## F03 · 摘录与自己的想法并排

**问题：** 附件摘要可以查阅，但用户读到一段话后的判断还缺少明确来源。

**来源：** [Zotero 标注与笔记](https://www.zotero.org/support/pdf_reader)、[Reader 高亮与笔记](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes)。

**流程：** 在资料页段选择原句 → 保存摘录 → 输入自己的理解 → 生成一条带来源的普通笔记 → 原文引用在右侧打开对应页段 → 导出同时标记摘录、用户表达与 AI 回应。

**适配：高；优先 P1。** 0.4 已有资料页段，新增准确摘录定位与“摘录→想法”的闭环；摘录本身始终属于参考资料。

**稳定性成本：中。** 文件哈希、段 ID、文字偏移与逐字快照共同校验；提取器升级不能让旧引用跳到另一段。**最小验证：** 中文两页 PDF、DOCX、长 TXT 各 10 段，删除资料后笔记保留来源占位，重新恢复可核对原引用。

## F04 · 选几条笔记，回答一个具体问题

**问题：** 单条讨论太局部，全线程回顾又可能太宽；用户需要自主指定“这几条一起看”。

**来源：** [Granola 多内容聊天](https://docs.granola.ai/help-center/getting-started/granola-101)、[Flownote 材料范围与分阶段整理](https://github.com/tob124/flownote/blob/217c5db780e37ee83c6961c250f20f9c70d105cf/src/main/services/thinking-service.ts#L200)。

**流程：** 搜索或多选笔记 → 核对标题、正文版本和条数 → 写一个问题或选择“变化／矛盾／未解决问题”模板 → 排队分析 → 展示实际覆盖范围、用户明确表达、AI 推测和引用 → 保存为独立回顾 → 用户决定是否进一步提出认知建议。

**适配：很高；优先 P1。** 不重新归类，不默认修改认知；内部观察先完成，外部资料补充另行发起。

**稳定性成本：中。** 版本固定、删除排除、分段覆盖、任务取消和部分完成。**最小验证：** 12 条重复／相反／更正后的笔记；中途编辑一条，结果须显示过期；跨页引用与返回保持阅读位置。

## F05 · 主动选资料，组成一次讨论的参考范围

**问题：** 0.4 的讨论可以选择关联资料，但独立资料跨笔记复用还不顺手。

**来源：** [NotebookLM 选定来源聊天](https://support.google.com/gemininotebook/answer/16179559?hl=en)。

**流程：** 在回复入口打开“本次参考” → 从全部资料选择文件或页段 → 确认可读取范围 → 提问 → 回答标明实际使用资料 → 可保存参考组合供下次选择，但每次仍显示当前范围。

**适配：高；优先 P2。** 不自动把所有附件塞入上下文，不把文件作者观点当成用户立场。

**稳定性成本：中。** 大文件分段、多个文件同名、未下载原件、资料删除及版本变动；引用不能指向未读取部分。**最小验证：** 3 个文件中只勾选 2 个，答案不得引用第三个；资料不可用时说明缺失并保留问题草稿。

## F06 · 温和回看与“这条我已经看过”

**问题：** 长期保存后很多想法再也没有回来，机械每周总结又可能造成负担。

**来源：** [Readwise 回看](https://docs.readwise.io/readwise/docs/faqs/reviewing-highlights)、[Capacities 已回看状态](https://docs.capacities.io/reference/dates-and-daily-notes)。

**流程：** 用户选择回看范围与频率 → 提示少量旧内容 → 展示当时原文和后续更正 → 标记已看、以后再看或写一条新理解 → 新理解关联旧笔记；关闭提示仍可手动进入。

**适配：高；优先 P2。** 阅读本身不调用 AI；每周回顾提示与结构整理敏感度继续分开。

**稳定性成本：低至中。** 提醒去重、跨重启、时区和推迟状态；不按完成率评判用户。**最小验证：** 模拟 4 周，有新增、无新增、全部已看、提醒关闭；不反复弹出同一批，也不自动收费。

## F07 · 阅读推荐与回应反馈闭环

**问题：** 建议是否相关、是否读过、是否希望少评论，目前缺少持续反馈。

**来源：** [Flownote 推荐反馈与研究依据](https://github.com/tob124/flownote/blob/217c5db780e37ee83c6961c250f20f9c70d105cf/src/renderer/components/ThoughtPanel.tsx#L128)。

**流程：** 对具体问题主动找相关资料 → 每张卡说明问题、观点、相关理由、局限与证据 → 标记有帮助、已读或不相关 → 后续同依据不重复推荐 → 有新依据时解释再次出现原因 → 用户可撤回反馈并把阅读心得保存为新笔记。

**适配：高；优先 P2。** 先做可核对反馈，不把一次“不相关”扩大为全库偏好。普通回应另提供“少对这类记录评论”，可在设置撤回。

**稳定性成本：中。** 推荐身份、范围、依据版本及拒绝抑制持久化；来源打不开不能标为已核实。**最小验证：** 10 张推荐，重复发起、更正问题、新增来源、撤回反馈；已有内部观察不能因外部资料失败消失。

## F08 · 导入录音，得到可核对转录

**问题：** 用户已有音频，但系统听写不能处理录音文件。

**来源：** [Otter 转录与导出](https://help.otter.ai/hc/en-us/articles/360047733634-Export-conversations)。

**流程：** 选择音频 → 本机先保存原件并展示时长与转录方式 → 用户确认处理 → 分段转录与时间戳 → 用户核对、修改 → 保存为资料，明确选择自己的话才生成普通笔记 → 摘要与讨论引用可回放对应片段。

**适配：中高；优先 P2 试验。** 先音频文件导入，再内置录音。DeepSeek 文本调用不能代替语音识别，需要单独选择服务或本地模型。

**稳定性成本：高。** 文件格式、识别服务、音频分段、时长与费用、断点恢复及原件同步。**最小验证：** 10 段中文 1–10 分钟录音，噪声、数字、人名和多说话者；错词可修正，无法识别不制造用户立场。

## F09 · Windows 内置个人语音备忘

**问题：** 灵感需要快速录下来，直接听写容易来不及核对。

**来源：** [Tana 语音备忘的源材料与结构化结果](https://outliner.tana.inc/learn/features/mobile-voice-memos)、[Notion 录制阶段](https://www.notion.com/help/ai-meeting-notes)。

**流程：** 用户点开始并授权麦克风 → 明确录音状态、暂停、停止 → 录音立即本机落盘 → 独立转录任务 → 核对正文再保存笔记 → 失败可回听或重试。关闭窗口先保存录音，不依赖网络完成转录。

**适配：中；暂缓到 F08 稳定后。** 本轮 Win+H 入口继续保留；候选限定个人麦克风备忘，会议系统音频捕获另行评估。

**稳定性成本：高。** 权限、设备切换、系统休眠、分段容器与崩溃恢复。**最小验证：** 断网、突然退出、换麦克风和权限拒绝；已录片段不能丢，失败不能显示录音仍在继续。

## F10 · 转录润色对照与个人词表

**问题：** 识别出来能读，但润色可能改变否定、程度和专有名词。

**来源：** [Superwhisper 识别与语言模型处理分开](https://superwhisper.com/models)。

**流程：** 查看原始转录 → 可选添加个人词表或润色 → 前后差异标出 → 逐项接受或全体保留原转录 → 最后确认正文。原音频和原始识别结果始终可查。

**适配：中高；暂缓到 F08 后。** 不把 AI 润色叫作“用户原话”，未确认结果属于派生资料。

**稳定性成本：中。** 跨段差异、数字与否定保护、词表误替换、重新转录版本。**最小验证：** 30 段含否定、药名、金额、百分比和口语停顿的合成转录；润色出错可完整还原且不自动发送。

## F11 · 扫描 PDF 的按页 OCR

**问题：** 无文字 PDF 目前只能说明未提取，用户无法检索内容。

**来源：** [Heptabase PDF/OCR 能力](https://support.heptabase.com/en/articles/12990121-plans-and-pricing)。

**流程：** 检测页面文字缺失 → 提示需要 OCR → 用户选择页范围和本地／云端方式 → 保存页图与识别结果 → 标记低质量或未完成页 → 用户核对后建索引 → 摘要只声明已处理页，引用能回到页图。

**适配：高；优先 P2 独立试验。** 图片、手写和扫描件能力须分别说明；不让 OCR 重模型拖慢启动。

**稳定性成本：高。** 模型体积、中文版面、识别坐标、内存、云端费用与机密资料选择。**最小验证：** 20 页中文扫描，包含双栏、表格、倾斜和空白页；逐页失败不毁掉已完成页，错误页可重做。

## F12 · 小范围问题白板

**问题：** 对少量相关想法，空间排列比长时间线更容易比较。

**来源：** [Heptabase 白板与卡片结构](https://support.heptabase.com/en/articles/17060792-heptabase-mcp-tool-reference)。

**流程：** 从已有问题或多选内容打开白板 → 放入 12–20 张引用卡 → 分组或连线并写关系说明 → 点卡片回到原文 → 布局保存；原文更正时卡片提示版本变化。

**适配：中；优先 P3。** 白板是现有笔记的视图，不建立第二份正文，也不自动生成全库知识图谱。

**稳定性成本：中高。** 键盘替代操作、缩放、布局恢复、大量连线和窄窗口。**最小验证：** 20 张卡片、两组关系，重启、删卡、正文更正和导出都保持同一来源。

## F13 · 资料学习问题

**问题：** 读完摘要容易觉得理解了，却不一定能解释资料论证。

**来源：** [RemNote 资料阅读与学习问题](https://help.remnote.com/en/articles/6690975-learning-from-pdfs-and-files-with-the-remnote-reader)。

**流程：** 选读一个已读取资料范围 → 主动生成 3–5 个理解问题 → 自己作答 → 回看对应原文 → 保存理解笔记；可选择是否以后复习。

**适配：中；优先 P3。** 先理解和核对，不自动把所有笔记变为卡片，也不把 AI 答案当作已确认认知。

**稳定性成本：中。** 题目依据、答案泄露、错误反馈与资料版本。**最小验证：** 5 篇资料，每题能定位具体段落，范围不足允许不出题；用户回答不被 AI 自动改写。

## F14 · 待验证判断与轻量后续状态

**问题：** 回顾里的追问可能一直悬空，用户不记得哪些已获得新证据。

**来源：** [Capacities 从日记内容保留行动来源](https://docs.capacities.io/reference/use-cases/daily-notes)。

**流程：** 把一项追问标为待观察 → 用户选择提醒或不提醒 → 后续记录可关联它 → 标记有新证据、已解决或暂不处理 → 解决时保存自己的结论和证据，不自动修改原笔记或认知。

**适配：高；优先 P2。** 只做想法的后续状态，不扩展成项目管理器；AI 建议不会自动成为待办。

**稳定性成本：中。** 状态版本、撤销、旧引用和重复提醒；重新打开需保留旧结论。**最小验证：** 10 个追问各经历挂起、解决、重开，引用删除后仍能理解处理历史。

## F15 · “这条不交给外部 AI”

**问题：** 有些记录只想保存和本地搜索，不希望自动分类、回顾或讨论把它传出去。

**来源：** [Reflect 对 private 笔记在调用点再次检查](https://github.com/team-reflect/reflect-open/blob/master/docs/privacy.md)。

**流程：** 保存前或卡片菜单设置排除 AI → 本机检索照常 → 分类、历史整理、回顾、讨论和外部检索全部排除 → 已排队任务停止使用 → 每次调用前重新检查 → 解除后由用户明确决定是否补做 AI。

**适配：高；优先 P2。** 标签应明确“不交给外部 AI”，不能暗示“不上传坚果云”；思想库云端托管是另一设置，历史已发送内容也不能假称撤回。

**稳定性成本：中高。** 所有上下文组装入口、附件关联和进行中请求都要统一保护，恢复后仍生效。**最小验证：** 在分类、回顾、讨论、整理和资料任务中放入可追踪合成文字，模拟服务收到的请求均不包含它；改标记和重启也不泄露。

## 建议的下一轮组合

优先 **F01 保存查询 + F03 摘录到想法 + F04 选定笔记分析**。三者组成“找到旧想法 → 核对资料 → 明确范围观察 → 留下新判断”的完整路径，直接改善长期使用，而新增后台复杂度较少。

第二组可选 **F05 资料范围 + F07 推荐反馈 + F14 待验证判断**，适合把 Flownote 的研究能力进一步打磨成可追踪的思考过程。F02、F06、F15 可以按关联、回看或隐私的实际需要择一加入，避免一个版本同时增加过多入口。

语音优先试验 **F08 文件转录**，确认准确度、恢复与成本后再做 F09/F10。OCR 的 F11 单独验收，不与语音同时引入两个重处理链。F12 白板、F13 学习问题暂缓，先验证用户是否确实需要空间整理或记忆复习。

本轮不建议：全库自动知识图谱、自动多代理研究、未经确认的认知改写、完整会议机器人、多台 Windows 并发维护。它们会扩大同步、引用、费用和解释成本，且当前需求尚不足以证明收益。

选择时可直接报候选编号。下一轮施工方案应只覆盖选定组合，逐一写清数据版本、界面入口、失败恢复和可验证的完成条件。
