# ChatNoteUki

只面向 Windows 的个人认知伙伴。你直接记录，AI 自动归入思考线程，为每条笔记生成标题、一句话概述和简短回应；你的原话与思想演变永久保留。

## 安装与首次使用

1. 安装 `release/ChatNoteUki-0.1.0-Setup-x64.exe`，或运行 `release/win-unpacked/ChatNoteUki.exe`。
2. 打开「设置与数据」，填写自己的 DeepSeek API key。默认使用 `deepseek-flash`，自动分类、标题、概述和简短回应合并为一次调用。
3. 可立即离线记录。未配置 key 的记录先显示原文首行和「待生成」；配置后依序处理。失败任务仅手动重试，已成功的任务不重复调用。
4. 可选：配置坚果云 WebDAV，填写服务器地址 `https://dav.jianguoyun.com/dav/`、坚果云账户和**第三方应用密码**，默认目录 `ChatNoteUki`。不要填写坚果云登录密码。

本地数据位于 `%APPDATA%/ChatNoteUki/`（Electron 的 Windows userData 目录）。卸载保留数据；API key 和 WebDAV 密码使用 Windows DPAPI 加密，只能由对应 Windows 用户解密。程序源码、安装包、云端备份均不包含你的凭据。

高级用途可通过进程环境变量 `UKI_DATA_DIR` 指定独立本地资料目录；安装包验收使用此方式隔离测试数据，不操作你的日常思想库。

## 手机输入

手机使用现有编辑器修改坚果云目录下的 `inbox.txt`；本项目不制作手机应用。示例：

```text
我现在如何理解职业路线？
这行仍属于同一条笔记。

今天关于城市密度的新想法。

我想重新检验之前的判断。
```

空行分隔笔记，单次换行保留在原文里。兼容 UTF-8（含 BOM）及 CRLF、LF、CR、混合换行和带空格的空行。最后一条不必以换行结尾；空白内容不导入。

先完成手机上传，再启动 Windows 或点击「同步」。Windows 按文件顺序保存原文、归档到云端并发布恢复清单，随后使用强 ETag / `If-Match` 条件清空。AI 失败不会影响已保存的原文，也不会阻止安全清空。

发生追加冲突时只导入新增部分；既有内容被改写时，保存冲突快照并暂停清空，请核对手机文件。服务器不支持条件写入或 inbox 没有强 ETag 时，程序保留原文并显示原因，不无条件清空。

**限制：**条件写入只能防止服务器当时的并发覆盖，不能阻止手机编辑器稍后上传旧副本。不要在 Windows 导入时让手机继续编辑旧副本；读到旧内容重新出现时先核对。相同文字可以是你有意记录的新笔记，程序不会永久按内容去重。

## 思考与观点版本

- 主入口无须分类；已有线程中也可以继续记录或选择「继续讨论」。只有主动讨论允许手动选择 Pro。
- 标题和一句话概述用于列表与搜索；点击记录查看完整原文和 AI 回应。派生信息从不覆盖原文。
- 搜索覆盖原文、标题、概述和回应，支持中文及短关键词。
- 「回看历史，提出认知差异」生成带原文引用的候选版本。接受、修改后接受或拒绝均保留历史；过期建议不能直接接受。
- 当前认知、近期原文与检索到的相关历史组成有限上下文；单次输入保守控制在 8,000 tokens 内。超长原文仍能保存，但可能需拆分后再处理。
- 每日输入默认 100,000 tokens、输出 12,000 tokens，可在设置调整。网络中断可能已被供应商计费，因此仅显示已返回结果的实际用量，不宣称精确账单。
- 未确认的请求按单次最大输入及输出保守计入当日预算，避免断网或重启绕过预算；返回实际用量后替换预留额。明确授权失败、余额不足和限流响应会释放预留额。

## 完整备份与换机

云端目录包括 `inbox.txt`、`imports/` 原文件归档、`events/` 不可变思想事件以及 `manifest.json` 版本化恢复清单。SQLite 只在本地运行，禁止把打开中的数据库直接放进坚果云同步目录。

桌面记录、AI 元信息、回应、认知审批和任务状态先本地提交，通过持久化事件队列异步备份。断网时记录照常可用；网络恢复后点击「同步」重试。启动和手动同步才读取手机 inbox，不在后台持续轮询。

换机：停止旧电脑同步，在新电脑的空白资料库配置相同坚果云账户和目录，保存设置，再点击「从云端恢复并接管」。恢复后会重建原文、标题、概述、线程、对话、认知版本与未完成任务；旧电脑将因维护设备不同停止写入。凭据不随思想库迁移，新电脑需重新填写。首版不支持多台 Windows 并发编辑。

云端思想数据为可读 JSON 和文本，经 HTTPS 传输，不是端到端加密。不要把应用凭据写入笔记。已发起但中断的 AI 任务标记为失败，防止重启后自动产生重复费用。

## 开发与检查

需要 Windows 10/11 x64、Node.js 24 和 npm。SQLite 使用 Electron/Node 自带的 `node:sqlite`，不依赖本机编译器或外部数据库。

```powershell
npm ci
npm run dev
npm test
npm run test:desktop
npm run dist
npm run verify:secrets
```

`npm test` 使用模拟 AI/WebDAV，不产生模型费用。桌面测试也模拟 AI，并使用 `.local/` 隔离数据。`node scripts/live-smoke.mjs` 是显式真实联调入口，需仅为该进程设置 `DEEPSEEK_API_KEY`；最多 3 次 Flash 请求，报告不包含 key，测试凭据仅 DPAPI 加密保存于被 Git 忽略的 `.local/`。

GitHub Actions 在 Windows 上运行类型检查、单元测试、桌面测试和安装包构建，生成可下载的安装包 artifact。首次原型安装包未签名；应用升级暂为手动安装，不自动删除数据。

## 首版边界

只做 Windows 10/11 x64；没有手机应用、向量数据库、知识图谱、联网研究或多人格。坚果云服务器真实条件写入能力会在首次连接时用独立临时文件验证。正式发布前需用自己的第三方应用密码完成真实 WebDAV 联调，模拟测试不替代真实验证。
